- Keep the administration Settings section order in browser localStorage with stable section IDs; this preserves each administrator's layout without changing shared operational settings or access rules.
- Read archived order payloads through the security-invoker `order_history_readable` view, paginating full history; it omits unused embedded product images to avoid timeouts while preserving original archives and site RLS. Writes still target `order_history`.
- Only the order owner may answer a proposed delivery time through `respond-to-delivery-time`; email token responses remain separate, preventing administrators from answering for customers.
- `notify_delivery_response` only inserts admin notifications while `is_site_open(restaurant)` is true, so staff alerts follow each site's configured opening hours.- Order confirmation emails are sent by the `trg_order_confirmation_email` trigger (status → confirmed) calling `send-order-confirmation-email` via pg_net, deduplicated by `orders.confirmation_email_sent_at`; email failures never block Stripe capture, status change or ticket printing.
- Failed address-validation emails are listed and re-sent by the Super-Admin-only `admin-email-verifications` function (role checked in `user_roles` with the service client, since `is_super_admin` returns false without a user session).
- Verification delivery failures are observed independently by `monitor-verification-delivery` using delivery history; queue retry counts never drive application alerts, so email transport updates preserve Super Admin notifications.
- Une commande confirmée (capture_status captured ou statut au-delà de pending) ne peut plus être annulée : l’option « Annulée » est masquée dans AdminOrdersPage et cancel-order refuse côté serveur ; seule une commande encore « En attente » est annulable.
- App emails send directly through the managed email API via `_shared/sendAndLog.ts`, which also appends the outcome to `email_send_log` so the Super Admin verification alert trigger and history views keep working; browser-triggered invoice and delivery-time emails go through the role-checked `send-app-email` function, never a generic sender.
- Validate delivery address completeness using the function-local `addressValidation.ts` helper and structured geocoding components; raw-word bans can reject legitimate street names.
